# 단계: 설계

기능: $FEATURE

## 출력 (이 파일 하나만 쓴다)
$WORK/DESIGN.md

## 입력 (읽기만, 절대 수정 금지)
- $ROOT/PRD.md — 요구사항 ID(FR-xxx)·수용 기준·의사결정. **가장 먼저 읽는다**
- $ROOT/src/ — 실제 코드 (아직 없을 수 있다. 없으면 신규 구축이다)

## 할 일
1. `$ROOT/PRD.md` 에서 이 기능에 해당하는 **FR ID 를 전부 찾아** 수용 기준을 읽는다.
2. `$ROOT/src` 의 관련 코드를 읽고 현재 구조를 파악한다.
3. 이 기능의 설계를 `$WORK/DESIGN.md` 에 쓴다.

## DESIGN.md 필수 섹션
- STATUS 라인 (첫 줄)
- **대응하는 FR ID 목록** — 각 ID 의 수용 기준을 PRD 원문 그대로 인용한다.
  PRD 에 없는 것을 설계에 넣으려면 그것이 범위 밖이 아닌 이유를 쓴다
- 변경 대상 파일 목록 (경로 명시, 신규/수정 표시)
- 공개 인터페이스 (함수 시그니처 / 자료구조 / CLI 옵션)
- 데이터 흐름 (입력 → 처리 → 출력)
- 검증 기준: 이 기능이 "됐다"는 걸 무엇으로 확인하는지 케이스 수준으로.
  **pytest 로 확인되는 것과 사람이 직접 돌려봐야 하는 것을 나눠서 쓴다**
  (아래 "검증 가능성" 참조)
- 하지 않는 것 (범위 밖 명시)

## 이 저장소의 제약 — 설계가 여기에 걸리면 방향을 바꿔라

**절대 무너뜨리지 않는다** (근거는 PRD.md):
- **LLM 호출은 세션 종료 시에만.** 정상 경로 1회, 스키마 실패 재시도를 포함해도
  세션 상한 2회. 저장 이벤트 중 호출은 0회다 (FR-030)
- **외부 전송 전에 로컬 secret scan 을 통과해야 한다.** 탐지 시 기본 정책은
  전송 중단이다. 응답 스키마의 `sensitive_data_detected` 는 사후 신호일 뿐
  방어선이 아니다 — 그게 찍힐 때는 이미 전송된 뒤다 (FR-036)
- **Discord 로는 요약만 나간다.** payload 에 코드 원문이나 diff 라인이 들어가면
  안 된다 (FR-051)
- **변경이 없으면 OpenAI 호출도 Discord 전송도 0회다** (FR-035)
- **diff 는 difflib 하나다.** git 에 의존하지 않는다 — git 설치 여부·저장소 여부와
  무관하게 같은 결과가 나와야 한다 (FR-020, 개정 근거 C-04)
- **외부 상시 서버를 두지 않는다.** 프로세스 수명 = 수업 세션
- **로컬 산출물 보존이 외부 전송보다 우선한다.** 각 단계 산출물은 다음 단계 실패와
  무관하게 남는다. 유일한 예외가 비밀값 탐지다 (PRD 12절 복구 원칙)

**범위 밖** (제안하지 말 것): 다중 디렉터리·프로젝트 전체 감시 · 저장할 때마다 요약 ·
실시간 코딩 조언 · 로컬 LLM · IDE 플러그인 · GUI · 사용자 계정 · 중앙 대시보드 ·
팀원이 도구를 실행하는 기능 (팀원은 수신자다)

**외부 API 표면은 이 환경에서 확인할 수 없다.** OpenAI 요청 파라미터명, Discord
Webhook payload 필드 같은 것은 저장소 안에 정본이 없다. 이런 주장은 설계에 `추정`
으로 표시하고, **어댑터 뒤로 격리해서 틀렸을 때 고칠 자리가 한 곳이 되게** 설계해라.
다음 단계(판단 검증)가 이걸 `미확인` 으로 잡는다.

## 검증 가능성 — 설계 단계에서 정해진다

**검증 수단은 pytest 하나뿐이다.** OpenAI·Discord 에 실제로 붙는 검증은 불가능하다.
파일시스템 이벤트는 돌릴 수는 있지만 OS·타이밍에 의존해서 불안정하다.

검증 기준을 쓸 때 두 가지로 나눠라:
- **[테스트 가능]** — 순수 함수로 돌릴 수 있는 것. diff 생성, secret 패턴 매칭,
  메시지 렌더링, 스키마 검증, 파일 선택(allowlist·제외 패턴), 종료 코드 매핑,
  debounce 병합 판정
- **[사람 확인 필요]** — 못 돌리는 것. 실제 IDE 저장 감지, Ctrl+C 타이밍,
  실제 API 호출, exe 단독 실행

**검증 가능한 쪽으로 구조를 밀어라.** watchdog 핸들러나 CLI 진입점 안에 로직을
묻지 말고 순수 함수로 빼면 그만큼 [테스트 가능] 으로 넘어간다. 이 프로젝트에서 그
축은 **부작용(파일 읽기·네트워크·시계)과 판정 로직의 분리**다.

## 게이트에 걸리는 것 — 설계에 넣지 말고 STATUS: BLOCKED 로 올려라
- 의존성 추가/제거 (`pyproject.toml`)
- pytest·ruff·mypy 설정 변경
- PRD 의 P0 요구사항과 충돌하는 것
- LLM 호출 횟수 상한을 늘리는 것
- 비밀값 탐지 시 기본 정책(전송 중단)을 바꾸는 것

## 금지
- 코드를 쓰지 않는다. 시그니처와 스펙까지만.
- 설계에 필요한 정보가 없으면 추측하지 말고 STATUS: BLOCKED.
