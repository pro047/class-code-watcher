# 단계: 구현

기능: $FEATURE

## 출력 (이 파일 하나만 쓴다)
$WORK/IMPL.md

## 입력 (읽기만, 절대 수정 금지)
- `$WORK/DESIGN.md` — 이 설계를 그대로 구현한다
- `$WORK/JUDGE.md` — 설계 주장의 감사 결과. **`반박` 판정이 있으면 그 주장에 기댄
  부분을 그대로 구현하지 마라.** 판정과 설계가 충돌하면 STATUS: BLOCKED
- `$WORK/FAIL_LOG.md` — 비어있지 않다면 이전 시도가 실패한 것이다. 같은 실패를 반복하지 마라
- `$ROOT/PRD.md` — 요구사항 원문. DESIGN.md 가 인용한 FR 의 수용 기준을 확인할 때만 본다

## 할 일
1. DESIGN.md 의 "변경 대상 파일 목록"대로만 수정한다.
2. 목록에 없는 파일을 건드려야 한다면 STATUS: BLOCKED. **단 아래 "낡은 테스트" 예외를 먼저 읽어라.**
3. 작업 요약을 `$WORK/IMPL.md` 에 쓴다.

## 낡은 테스트 때문에 막히면 — BLOCKED 가 아니라 인계다

구현이 기존 동작을 바꾸면 그 동작을 전제로 쓰인 **기존 테스트가 낡는다.** 스텁이
즉시 반환하던 것을 실제 루프로 바꾸면 그 스텁을 부르던 테스트는 안 돌아온다.
**이것은 구현 결함이 아니라 테스트가 낡은 것이다.**

너는 테스트를 못 고친다(아래 금지). 고칠 수 있는 것은 검증 단계다. 그런데 여기서
BLOCKED 를 올리면 **검증 단계가 시작조차 못 해서 아무도 고칠 수 없는 교착이 된다.**

그러니 아래 **세 조건을 전부** 만족하면 BLOCKED 를 올리지 말고 `STATUS: DONE` 으로
통과시킨 뒤, "다음 단계가 알아야 할 것"에 인계 항목을 써라:

1. 네가 담당한 소스 변경이 완결됐다 — 설계 2절 목록을 다 반영했다.
2. **소스만 놓고 보면 게이트가 녹색이다.** `ruff check src` 와 `mypy src` 가 통과한다.
   (게이트 명령을 실제로 돌려 확인해라. 안 돌려보고 이 판단을 하지 마라.)
3. 게이트를 붉게 만드는 원인이 **`tests/` 아래 파일에만** 있다.

인계 항목에는 이것을 정확히 써라 — 검증 단계가 추측하지 않게:

- 낡은 테스트의 **파일:줄**과 이름
- 왜 낡았는지 (무슨 동작이 어떻게 바뀌었는지)
- 바뀐 기대값 — 새 에러 문자열, 새 종료 코드, 새 필드명 등 **구체적인 값**
- 막힘을 푸는 방법 한 가지 이상 (예: 어떤 함수를 monkeypatch 하면 되는지)

**이 예외를 넓게 쓰지 마라.** 소스 자체가 게이트를 붉게 만들면 그건 네 일이다 —
통과시키지 말고 고쳐라. 조건 2를 실행으로 확인하지 않은 채 "테스트 탓"으로 넘기는
것은 이 예외의 오용이다. 판단이 서지 않으면 BLOCKED 가 맞다.

죽은 이전 주행이 남긴 테스트 파일이 게이트를 붉게 만드는 경우도 같다 — 지우거나
고치지 말고, 어느 파일이 왜 붉은지만 인계해라.

## IMPL.md 필수 섹션
- STATUS 라인 (첫 줄)
- 실제로 수정한 파일 목록 (설계와 다르면 그 이유)
- 설계와 달라진 점 (없으면 "없음")
- 다음 단계(검증)가 알아야 할 것
- **실행해서 확인한 것 / 확인하지 못한 것** — 돌린 명령과 실제 출력만 쓴다.
  못 돌렸으면 그 이유를 쓴다(예: mypy 미설치 → 타입 검사 불가).
  "될 것으로 보인다"는 금지

## 이 저장소의 코딩 규칙
- **콘솔 출력 문구와 코드 주석은 한국어.** 사용자가 한국인이다
- 주석은 "왜"만 적는다. 코드를 읽으면 아는 "무엇"은 적지 않는다
- 주석 밀도는 주변 코드에 맞춘다
- **타입 힌트를 붙인다.** mypy 가 검증 목록에 있다
- **부작용과 판정 로직을 분리한다.** 파일 읽기·네트워크·시계는 얇게, 판정은 순수
  함수로. 다음 단계가 테스트를 쓸 수 있느냐가 여기서 결정된다
- **비밀값을 로그·콘솔·예외 메시지에 흘리지 않는다** (FR-003, FR-042).
  예외를 그대로 올리기 전에 메시지에 키·Webhook URL 이 섞였는지 본다.
  마지막 4자도 기본적으로 출력하지 않는 것이 이 저장소의 기준이다

## 손대면 안 되는 것 — 필요하면 STATUS: BLOCKED
- `pyproject.toml` 의 의존성 (패키지 추가/제거는 사람 승인 사항)
- pytest·ruff·mypy 설정 — `pyproject.toml` 의 `[tool.*]`, `pytest.ini`, `ruff.toml`,
  `mypy.ini`, `setup.cfg`, `conftest.py`. **새로 만드는 것도 포함이다.**
  검증 단계의 게이트 설정이라 셸이 지문으로 감시한다
- `.env` / `.env.example` / `.gitignore`
- `AGENTS.md`
- `PRD.md` (파이프라인 완주 후 사람이 갱신한다)

## 금지
- 테스트·검증 스크립트를 작성하지 않는다. 그건 다음 단계다.
- 설계를 바꾸지 않는다. 설계가 틀렸으면 BLOCKED.
- `pip install` 을 돌리지 않는다. 의존성이 필요하면 BLOCKED.
