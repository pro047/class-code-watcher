## 1. 수업 시작 직전 — C-30 준비 (1분)

**`cw:skip` 은 수업 중에 쓸 것이므로 미리 손에 익혀 둔다.** 오늘 확인할 새 기능이다.

수업 중 **연습용·낙서용 파일**을 하나라도 만들게 되면 그 **맨 위 첫 줄**에 이렇게 적는다:

```html
<!-- cw:skip -->
```
```javascript
// cw:skip
```

| 규칙 | 내용 |
|---|---|
| 위치 | **파일 맨 위.** 빈 줄은 건너뛰지만 **코드 뒤에 적으면 안 먹는다** |
| 대소문자 | 가리지 않는다 (`CW:SKIP` 도 된다) |
| 취소 | 수업 중에 그 줄을 **지우면 그 파일이 다시 요약에 들어온다** |
| 주의 | `cw-skip`(하이픈)은 **안 먹는다.** 콜론이다 |

> **연습 파일을 안 만들 것 같으면 일부러 하나 만들어라** — `scratch.js` 에 `// cw:skip` 을 적고
> 아무 줄이나 몇 개 쓴다. **이걸 안 하면 C-30 을 못 닫는다.**

## 2. 수업 세션 — 오전/오후로 나눠 돌린다

**하루 1세션이 아니다** (2026-09-09 운영 결정). TPM 천장(30,000) 때문에 하루치를 한 요청에
못 담는다. 나누면 적어도 오전이 통째로 사라지는 일은 막는다.

```powershell
python.exe -m class_watcher.cli watch <수업 폴더> --title "JS 이벤트"      # 오전. 점심때 Ctrl+C
python.exe -m class_watcher.cli watch <수업 폴더> --title "JS 이벤트 심화"  # 오후
```

| | |
|---|---|
| **제목을 반드시 넘겨라** | 생략하면 기본값 `JS 수업` 이 박히고 **두 세션이 같은 제목으로 나가 수신자가 구분 못 한다** |
| baseline | 오후 세션은 오전 종료 상태로 잡히므로 **중복이 없다** |
| 종료 | Ctrl+C **한 번.** (두 번 누르면 외부 호출이 취소되고 `aborted_by_user` 로 끝난다) |

**중간에 감시 루트를 열어 보지 마라.** 지금은 읽기만 하면 이벤트가 안 찍히지만(N1, 09-07 확인),
습관을 유지한다. 진행 상황은 `sessions/<세션>/events.jsonl`·`session.json` 으로 본다 — 감시 대상 밖이다.

## 3. 세션 직후 — 파일로 확인 (Discord 열기 전)

`sessions/<세션>/` 에서 본다. **오전·오후 두 세션 각각.**

### 3-1. ★ C-30 — `cw:skip` 이 실제로 먹었나 (새 항목)

| 볼 것 | 기대 |
|---|---|
| 종료 콘솔 | `[DIFF] … N개 건너뜀(opt_out)` 이 뜬다 |
| `final.diff` | `# skipped: scratch.js (opt_out)` **한 줄만** 있고 파일 내용이 없다 |
| `session.json` 의 `watched_files` | 그 파일이 `{"status": "skipped", "reason": "opt_out"}` |
| `prompt.json` | 그 파일에만 있던 단어가 **없다** |

**적어 둘 것:**
```
opt_out 파일 수 :        개
그 파일 내용이 final.diff·prompt.json 에 샜나 : 예 / 아니오
```

> 표식 파일**만** 바뀐 세션이면 `discord.skip_reason: "no_meaningful_change"` 로 전송이 생략되고
> 종료 코드 0 이다. 그것도 정상이다.

### 3-2. ★ C-29 — `syntax` 앞 기호가 살아 있나 (새 항목, **조건부**)

**오늘 수업에 연산자·증감 표기가 나왔을 때만 잰다.** `summary.json` 의 `keywords[].syntax` 를 훑는다.

| | 기대 |
|---|---|
| `+/*`·`--i`·`-=`·`+=`·`++`·`-x` 같은 값이 있나 | **없으면 이번엔 못 잰다** — C-29 는 열린 채로 남긴다. 실패가 아니다 |
| 있으면 → Discord 메시지의 그 줄 | `· 문자열 연산자  +/*` 처럼 **앞 기호가 그대로** 있다 |
| `discord_payload.json` 의 모든 줄 | `+` 나 `-` 로 **시작하는 줄이 0개** (FR-051) |

**적어 둘 것:**
```
syntax 에 앞 기호가 붙은 항목 :        개 (없으면 "0 — 못 잼")
그중 메시지에서 기호가 살아남은 것 :        개
+/- 로 시작하는 줄 :        개  (0 이어야 한다)
```

> **09-11 에는 여기서 `+/*` 가 `/*` 로 나갔다.** 그게 C-29 를 만든 결함이고 지금 고쳐져 있다.
> **가장 최근 JS 수업은 09-09 `15_문서객체모델_DOM조작.html` 이었다** — 다음 단원이 이벤트·비동기
> 쪽이면 연산자 표기가 안 나올 수 있다. 안 나오면 그렇게 적고 넘어간다.

### 3-3. N2 — 포맷터 노이즈가 얼마나 걷혔나 (C-24 + C-28)

| 볼 것 | 기대 |
|---|---|
| `session.json` 의 `watched_files` | 포맷만 저장된 파일이 `{"status": "skipped", "reason": "whitespace_only"}` |
| `change_stats` 의 `added_lines`/`deleted_lines` | 포맷터 줄 수만큼 부풀지 **않았다** |
| `final.diff` 안 | 내용은 같고 **들여쓰기만 다른 `+`/`-` 줄 쌍**이 없다 (C-28 이 걷어낸다) |

**적어 둘 것:**
```
final.diff 크기 :        자   (예산 60,000 대비      %)
change_stats    : +      / -
skipped 파일 수 :        개 (그중 whitespace_only:      개)
```

> **노이즈는 파일당 한 번뿐이다** (09-09 실측). prettier 가 손으로 쓴 파일을 **처음** 만질 때만
> 전체를 재들여쓰기하고, 그 뒤로는 안 건드린다. **그래서 오늘 새로 만드는 파일이 이 항목의
> 표본이다** — 이미 포맷된 옛 파일만 고치면 0줄이 나오고 아무것도 못 잰다.
>
> **0 을 기대하는 것이 아니다.** 대소문자(`<!DOCTYPE>`→`<!doctype>`)·자기닫힘 태그·**줄 접힘**은
> 공백이 아니라 안 걸러진다 (PRD C-24·C-28 의 명시된 한계).

### 3-4. 절단됐나 — H3 판정에 필요하다

`summary.json` 의 `truncated` 를 본다.

- `false` → 전량 들어갔다. **H3(절단 표시)은 이번에 못 잰다**
- `true` → `final.diff` 크기와 예산 대비 %를 적는다. 그리고 **4-3 으로 간다**

> **H1 은 09-08 에 닫혔다** — 답은 「예산 60,000 이 맞다, 다만 근거가 TPM 이지 diff 크기가
> 아니다」. `truncated: true` 는 이 계정에서 하루치로는 피할 수 없다. **그래서 오전/오후로 나눈다.**

### 3-5. 이상하면 적는다 (닫힌 항목들 — 회귀 감시용)

아래는 이미 실측으로 닫혔다. **평소대로면 아무것도 안 해도 된다.** 어긋날 때만 적는다.

| 확인 | 어긋나면 |
|---|---|
| `session.json` 의 `openai` 에 `error` 없고 `calls: 1` | `openai_timeout` 이면 `final.diff` 크기를 적는다 (C-22 는 90초로 세 세션 통과했다) |
| `keywords[]` 묶음 제목이 그날 내용을 담는 한국어 | 고정 6종으로 돌아갔거나 **오분류**가 있으면 그 항목을 적는다 (C-19) |
| `term` 이 16자에서 잘린 항목 없음 | 있으면 그 `term` (C-23) |
| 긴 계열이 `...getMinutes/getSeco` 처럼 잘림 | **잘리지 말고 둘로 나뉘어야 한다** (C-23·C-27 경계 절단) |

## 4. Discord — 전송 확인 (H4·C·H3)

### 4-1. H4 — 키워드 10건 이상이 400 을 안 받는가

`session.json` 의 `discord` 를 본다.

- `delivered: true` · `http_status: 204` → 통과
- `http_status: 400` → `chunks` 와 메시지 길이를 적는다 (`DISCORD_CONTENT_LIMIT=2000`)

> **키워드가 10건 미만이면 이번에도 못 닫는다** (09-08 은 8건이라 못 닫았다). 몇 건이었는지 적는다.

### 4-2. C — 모바일 첫 화면 (FR-050)

**휴대폰** Discord 앱에서 그 메시지를 연다.

- 기대: **스크롤 없이** 제목·메타·`요약` 본문·키워드 앞 1~2묶음이 한 화면
- `FIRST_SCREEN_MAX_CHARS` 산수(1,619 ≤ 2,000)의 실물 검증이다
- **스크린샷을 남긴다**

### 4-3. H3 — 절단 표시가 첫 화면에 보이는가

3-4 에서 `truncated: true` 였을 때만 해당한다.

- 기대: `[근거 일부 누락 …]` 이 **첫 화면 안에** 보인다
- 데스크톱에서는 09-08 에 3번째 줄로 확인됐다. **남은 것은 모바일 첫 화면 여부다**

## 5. D — 수신자 5인 (최종 합격선)

**이 제품의 합격선이다** (PRD 15절). 팀 채널에 나간 메시지를 두고 5인에게 묻는다.

> "이 메시지만 보고 오늘 무엇을 배웠는지 알겠습니까?"

- **5인 중 3인 이상**이 "알겠다" → **통과**
- 못 미치면 → **프롬프트 조정이고 4단계로 되돌아가는 일이다.** 5단계 범위가 아니다

> **어느 메시지로 묻는지가 중요하다.** **오늘 나간 것으로 물어라.**
> - 09-01 오후 메시지 → 거짓 라벨이라 답이 F9 에 오염된다
> - **09-11 메시지 → `syntax` 가 깎인 상태다** (C-29 결함). 쓰지 마라
