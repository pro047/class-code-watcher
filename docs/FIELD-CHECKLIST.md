> 열 항목이 닫힌다. 근거와 배경은 `HANDOFF.md`·`PRD.md` 에 있고 여기는 **할 일과 볼 것**만 적는다.

> 작성: 2026-09-06 · 대상 커밋: `e73755b` 이후 · 게이트 490 passed / ruff clean / mypy 17 files

| | 확인 | 어긋나면 |

> 얼마나 걷어내는지**를 재야 하므로 평소대로 두고 돌린다.

## 1. 수업 시작 전 — N1 (읽기만 해도 이벤트가 찍히는가)

**이것만 수업 전에 따로 한다.** 2분이면 끝나고, 수업 세션과 섞이면 판정이 흐려진다.

1. 빈 폴더 하나를 만들고 `.html` 이나 `.js` 파일 2~3개를 넣는다
2. `python.exe -m class_watcher.cli watch <그 폴더>` 로 감시를 켠다
3. **파일을 에디터로 열어서 읽기만 한다. 저장하지 마라.** 탐색기 미리보기·백신 검사도 같은 효과다
4. 30초 기다린 뒤 Ctrl+C

**볼 것:**

| | 기대 | 어긋나면 |
|---|---|---|
| 콘솔 | `변경 감지` 줄이 **0개** | FR-018 이 안 먹는다 — 그 줄의 `hash=` 를 적어 둔다 |
| `sessions/<세션>/events.jsonl` | **파일이 아예 없다** | 위와 같다 |
| `session.json` | `change_stats.events == 0` · `no_change: true` · `status: "completed"` | |
| 종료 코드 | `0` | |

> **개정 전에는 여기서 17건이 찍혔다** (2026-09-01 실측, C-25). NTFS `atime` 갱신을 watchdog 이
> "변경"으로 구독해서다. **macOS 에서는 재현 자체가 안 되므로 이 확인은 Windows 에서만 가능하다.**
>
> 안 찍히면 성공이다. 찍히면 `fsutil behavior query disablelastaccess` 출력을 같이 적어 둔다.

## 2. 수업 세션 — 평소대로 한 번 돌린다

```
python.exe -m class_watcher.cli watch <수업 폴더> --title "<오늘 수업 제목>"
```

**중간에 아무것도 확인하지 마라.** 감시 루트를 읽는 행위 자체가 예전에는 오탐을 만들었고,
지금은 안 만들지만 그걸 재는 게 1번이었다. 진행 상황을 보고 싶으면
`sessions/<세션>/events.jsonl` 과 `session.json` 만 본다 — 감시 대상 밖이다.

수업이 끝나면 **Ctrl+C 한 번.** (두 번 누르면 외부 호출이 취소되고 `aborted_by_user` 로 끝난다)

## 3. 세션 직후 — 파일로 확인하는 것 (Discord 열기 전)

`sessions/<세션>/` 에서 본다.

### 3-1. N2 — 포맷터 노이즈가 얼마나 걷혔나 (C-24)

| 볼 것 | 기대 |
|---|---|
| `session.json` 의 `watched_files` | 포맷만 저장된 파일이 `{"status": "skipped", "reason": "whitespace_only"}` |
| `change_stats` 의 `added_lines`/`deleted_lines` | 포맷터 줄 수만큼 부풀지 **않았다** |
| `final.diff` 크기 | — |

**적어 둘 것 — 이게 N2 의 산출물이다:**

```
final.diff 크기 :        자
change_stats    : +      / -
skipped 파일 수 :        개 (그중 whitespace_only:      개)
```

> **89,101자가 0 이 되지는 않는다.** 대소문자(`<!DOCTYPE>`→`<!doctype>`)·자기닫힘 태그·**줄 접힘**은
> 공백이 아니라 안 걸러진다 (PRD C-24 의 명시된 한계). **얼마나 줄었는지를 재는 것이지
> 0 을 기대하는 것이 아니다.**

### 3-2. H1 — 예산 60,000 이 맞는 값인가

`summary.json` 의 `truncated` 를 본다.

- `false` → **예산이 넉넉하다.** H1 닫힘
- `true` → 절단됐다. `final.diff` 크기와 함께 적어 둔다. 예산 재검토 대상이고 **F1 한계**(hunk 하나가
  예산을 넘는 경우)에 걸렸는지도 같이 본다

### 3-3. C-22 — 타임아웃 90초가 처음 제품 경로를 탄다

`session.json` 의 `openai` 블록을 본다.

- `error` 가 없고 `calls: 1` → 통과
- `error: "openai_timeout"` → **90초로도 모자랐다.** `final.diff` 크기를 적어 둔다
  (09-02 는 41,140 B 에서 15초로 터졌고, 같은 입력이 90초로는 성공했다)

### 3-4. C-19 문안 전체 — 첫 실측

`summary.json` 의 `keywords[]` 를 본다.

| | 기대 | 적을 것 |
|---|---|---|
| 묶음 제목 | 그날 내용을 담는 한국어 (`[객체 관련 메소드]` 처럼). 고정 6종이 아니다 | 제목 목록 |
| **오분류** | **0건** — 코드에 없는 것을 가리키는 라벨이 없다 | 있으면 그 항목 |
| `실습` 묶음 | 그날 직접 만든 함수·클래스가 여기 있고 **배열 맨 뒤** | |
| `confidence` | 항목마다 갈린다 (전부 `high` 면 의심) | |

### 3-5. C-23 미실측 두 줄

| | 확인 | 기대 |
|---|---|---|
| `term` 16자 | 잘린 항목이 있는가 | 없어야 한다. 있으면 그 `term` 을 적는다 |
| **묶음 분할** | `syntax` 가 60자에 걸릴 만큼 긴 계열이 있었나 | **잘리지 말고 둘로 나뉘어야 한다** (`...getMinutes/getSeco` 처럼 잘리면 실패) |

## 4. Discord — 전송 확인 (H4·H3·C)

### 4-1. H4 — 키워드 10건 이상이 400 을 안 받는가

`session.json` 의 `discord` 를 본다.

- `delivered: true` · `http_status: 204` → 통과
- `http_status: 400` → `chunks` 와 메시지 길이를 적어 둔다 (`DISCORD_CONTENT_LIMIT=2000`)

### 4-2. C — 모바일 첫 화면 (FR-050)

**휴대폰** Discord 앱에서 그 메시지를 연다.

- 기대: **스크롤 없이** 제목·메타·`요약` 본문·키워드 앞 1~2묶음이 한 화면
- `FIRST_SCREEN_MAX_CHARS` 산수(1,619 ≤ 2,000)의 실물 검증이다
- 스크린샷을 남긴다

### 4-3. H3 — 절단 표시가 첫 화면에 보이는가

3-2 에서 `truncated: true` 였을 때만 해당한다.

- 기대: `[근거 일부 누락 …]` 이 **첫 화면 안에** 보인다
- `truncated: false` 였으면 **이번엔 못 잰다** — H3 은 열린 채로 남는다

## 5. N3 — 이미 판정났다 (2026-09-06)

`no_change: false` 인데 `discord.skip_reason: "no_change"` 인 조합은 **사람이 모순으로 읽는다**고
판정됐다. D11 이 틀렸고 `notify.py` 에 6번째 사유 상수를 넣는 것이 후속 작업이다.

**이번 세션에서 할 일은 없다.** 다만 3-1 에서 `whitespace_only` 세션이 나왔다면
`discord.skip_reason` 값을 적어 두면 후속 작업의 근거가 된다.

## 6. D — 수신자 5인 (최종 합격선)

**이 제품의 합격선이다** (PRD 15절). 팀 채널에 나간 메시지를 두고 5인에게 묻는다.

> "이 메시지만 보고 오늘 무엇을 배웠는지 알겠습니까?"

- **5인 중 3인 이상**이 "알겠다" → **통과**
- 못 미치면 → **프롬프트 조정이고 4단계로 되돌아가는 일이다.** 5단계 범위가 아니다

> **어느 메시지로 묻는지가 중요하다.** C-19 형식(동적 묶음 제목·오분류 0건)으로 나간 것으로 물어라.
> 09-01 오후의 거짓 라벨 메시지로 물으면 답이 F9 에 오염된다.
