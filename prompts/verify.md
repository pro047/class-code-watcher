# 단계: 검증

기능: $FEATURE

## 출력 (이 파일 하나만 쓴다)
$WORK/VERIFY.md

## 산출물 외에 수정해도 되는 것
- `$ROOT/tests/test_*.py` — 테스트 파일 (신규 작성·기존 수정)

## 입력 (읽기만, 절대 수정 금지)
- `$WORK/DESIGN.md` — "검증 기준" 섹션이 테스트의 근거다
- `$WORK/IMPL.md` — 실제 구현 내용
- `$WORK/JUDGE.md` — 설계 주장 감사 결과

## 이 저장소의 테스트 환경

pytest. 셸이 `$TEST_CMD` 로 돌린다.

- 테스트 파일 위치: `tests/test_*.py`
- **수집된 테스트가 0개면 pytest 는 exit 5 로 실패한다.** 테스트를 안 쓰고 넘어가는
  경로가 없다는 뜻이다
- 임시 파일·디렉터리는 `tmp_path` fixture 를 쓴다. 저장소 안에 쓰지 마라
- 외부 호출은 `monkeypatch` 또는 `unittest.mock` 으로 막는다
- 테스트에도 타입 힌트를 붙인다 (mypy 가 검증 목록에 있다)

**돌릴 수 없는 것** — OpenAI·Discord 에 실제로 붙는 테스트는 쓰지 마라. `.env` 는
없거나 더미 값이다. 네트워크를 타는 경로는 전부 mock 대상이다.

**불안정한 것** — watchdog 의 실제 파일시스템 이벤트는 OS·타이밍·백신에 의존한다.
`sleep` 을 넣어 이벤트를 기다리는 테스트는 CI 와 다른 PC 에서 무작위로 깨진다.
**이벤트 수신 자체를 테스트하지 말고, 이벤트를 받은 뒤의 판정 로직**(debounce 병합,
경로 필터, 스냅샷 비교, 안정화 판정)을 순수 함수로 테스트해라. 실제 감지는
사람 확인 체크리스트로 넘긴다.

## 할 일

0. **IMPL.md 가 낡은 테스트를 인계했으면 그것부터 고친다.** 구현이 기존 동작을 바꾸면
   그 동작을 전제로 쓰인 기존 테스트가 낡는다 — 안 돌아오거나, 이미 무효인 값을
   단정한다. 구현 단계는 테스트를 못 고치므로 **너에게 넘긴다.** IMPL.md 의
   "다음 단계가 알아야 할 것"에 파일:줄·바뀐 기대값·푸는 방법이 있다.
   이걸 미루면 셸의 게이트가 붉은 채로 남아 네 새 테스트까지 통과하지 못한다.
   낡은 테스트는 **지우지 말고 새 동작에 맞게 고쳐라** — 지우면 그 기준의 회귀
   방어가 사라진다. 정말 무의미해진 케이스만 지우고, 지운 이유를 VERIFY.md 에 써라.

1. DESIGN.md 의 검증 기준을 `tests/test_*.py` 로 옮긴다. 기준 하나당 케이스가
   최소 하나씩 대응돼야 한다. **이전 주행이 죽으면서 일부 테스트 파일을 남겼을 수
   있다** — 처음부터 다시 쓰지 말고, 이미 덮인 기준을 확인한 뒤 모자란 것만 보태라.
2. **불변식 회귀 테스트.** 이번 변경이 아래를 깨뜨릴 수 있는 자리에 있으면 그걸
   고정하는 케이스를 넣는다. 해당 없으면 "해당 없음"이라고 쓴다.
   - LLM 호출은 세션당 정상 1회 / 상한 2회, 저장 이벤트 중 0회 (FR-030)
   - 외부 전송 전 secret scan 통과 필수, 탐지 시 기본 전송 중단 (FR-036)
   - Discord payload 에 코드 원문·diff 라인이 없다 (FR-051)
   - 변경 없음이면 OpenAI·Discord 모두 0회 (FR-035)
   - git 없이도 diff 가 생성된다 (FR-020)
3. **테스트로 못 덮는 것을 사람 체크리스트로 넘긴다.** "무엇을 하면 무엇이 보여야
   하는가" 수준의 재현 절차로 쓴다.

## VERIFY.md 필수 섹션
- STATUS 라인 (첫 줄)
- 작성한 테스트 파일과 케이스 목록
- 검증 기준 ↔ 테스트 케이스 대응표 (빠진 기준이 있으면 명시)
- 불변식 회귀 테스트 결과 (위 5개 각각: 넣음 / 해당 없음)
- 테스트로 덮지 못한 부분 + 사람이 확인할 것 체크리스트 (재현 절차)

## 중요
테스트 통과 여부는 이 세션이 판정하지 않는다. 파이프라인 셸이 `$TEST_CMD` 를 별도로
실행해서 판정한다. "통과할 것으로 보인다" 같은 문장을 쓰지 마라.

## 금지
- **소스 코드를 수정하지 않는다.** 고칠 수 있는 것은 `tests/test_*.py` 뿐이다.
  구현이 틀렸으면 테스트를 느슨하게 만들지 말고 STATUS: BLOCKED
- 패키지를 추가하지 않는다. 필요하면 STATUS: BLOCKED
- **pytest·ruff·mypy 설정을 수정하거나 새로 만들지 않는다.** `pyproject.toml`,
  `pytest.ini`, `ruff.toml`, `mypy.ini`, `setup.cfg`, `conftest.py` 포함.
  게이트를 느슨하게 만드는 가장 값싼 경로라 셸이 지문으로 감시한다 —
  fixture 가 필요하면 테스트 파일 안에 둬라
- `@pytest.mark.skip` / `xfail` / 항상 참인 단언으로 케이스 개수만 채우지 않는다
