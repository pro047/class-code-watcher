# 수정 계획 — 키워드 syntax 앞의 `+`/`-` 가 Discord 메시지에서 잘린다

상태: **계획만. 코드 미변경.** 브랜치 `fix/syntax-leading-sign` (main `18e8f40` 기준)

## 1. 증상

2026-09-11 「파이썬 자료형」 세션(`20260911-090702-f145`) 실전송본.

| 위치 | 값 |
|---|---|
| `summary.json` → `keywords[].syntax` (모델 출력) | `+/*` |
| `discord_payload.json` → Discord 메시지 | `· 문자열 연산자  /*` |

모델은 옳게 냈고 **렌더러가 `+` 를 지웠다.** 수신자는 `/*` 를 C 주석 시작으로 읽는다 — 틀린 정보다.
같은 규칙으로 `--i`·`-=`·`+=`·`-x`(음수)·`++` 가 전부 앞 기호를 잃는다. 연산자 수업마다 재발한다.

## 2. 원인

- `notify.py:281-288` `_fold()` — 모든 모델 문자열에 `lstrip(" \t+-")` 를 건다. 모델 문자열이 diff
  라인처럼 시작하지 못하게 하는 FR-051 방어선이다.
- `notify.py:427-437` `_keyword_lines()` — syntax 에도 `sanitize_line` 을 균일하게 건다. 주석이 이
  손실을 알고 받아들였다:
  > `--i` 처럼 +/- 로 시작하는 표기는 앞 기호를 잃지만, 예외를 두면 FR-051 방어선이 "렌더가
  > syntax 를 줄 맨 앞에 두지 않는다"는 배치 순서에 의존하게 된다. P0 를 배치에 걸지 않는다.
- 그런데 **syntax 는 구조상 줄 맨 앞에 올 수 없다** — 항상 `· {term}  {syntax}` 의 뒤쪽이다.
  줄 앞 기호를 지우는 방어가 줄 앞에 오지 않는 값의 정보를 지우고 있다.
- **줄 단위의 최종 검사는 런타임에 없다.** `find_diff_lines()`(`notify.py:623`) 는 테스트에서만
  쓰인다. 지금 P0 는 "필드마다 앞을 지운다"는 입력 쪽 규칙 하나에 걸려 있다.

## 3. 방침

**방어선을 필드 단위에서 줄 단위로 옮긴다.** 줄 단위 불변식은 배치와 무관하므로 원래 주석이 걱정한
"배치 의존"이 생기지 않고, syntax 는 정보를 잃지 않는다.

| 단계 | 변경 |
|---|---|
| ① syntax 는 앞 기호를 남긴다 | `_keyword_lines` 에서 syntax 만 개행 접기·길이 clamp 만 하고 `+`/`-` 는 지우지 않는다. `_fold` 에 `strip_signs: bool = True` 인자를 두거나 syntax 전용 `sanitize_inline()` 을 둔다 |
| ② 줄 단위 최종 가드 | `render_message()` 의 마지막에서 `+`/`-` 로 시작하는 줄에 공백 한 칸을 붙인다. `_hard_wrap`(`notify.py:559`) 이 잘린 조각에 이미 쓰는 방식과 같다. 정상 경로에서는 아무 줄도 걸리지 않는다 |
| ③ 나머지 필드는 그대로 | term·concept·summary·질문·확인할 점은 `_fold` 의 앞 기호 제거를 유지한다. 줄 맨 앞에 올 수 있는 값이고, 문장 앞의 `- ` 는 정보가 아니라 머리표다 |

①만 하면 P0 가 배치에 걸리고, ②만 하면 syntax 손실이 그대로다. **둘을 같이 한다.**

### 검토한 대안

| 대안 | 채택 안 한 이유 |
|---|---|
| syntax 를 백틱으로 감싼다 (`` `+/*` ``) | 콘솔(cp949)·Discord 양쪽에 같은 문자열이 나간다. 백틱이 콘솔에 그대로 찍히고, 11.4 형식 명세를 바꾼다 |
| 프롬프트에서 "syntax 를 +/- 로 시작하지 마라" | 모델이 따르지 못한다 (C-20 과 같은 교훈). `+` 연산자를 정확히 쓰는 것을 막는 지시이기도 하다 |
| 앞 기호를 전각(`＋`)으로 치환 | 코드 표기가 코드가 아니게 된다. 복사해 쓰면 틀린다 |

## 5. 테스트 계획

| # | 테스트 | 기대 |
|---|---|---|
| T1 | syntax `+/*` · `--i` · `-=` · `++` · `-x` 렌더 | `· 문자열 연산자  +/*` 처럼 앞 기호가 남는다 |
| T2 | 기존 `test_diff_shaped_model_strings_never_render_as_diff_lines` | **수정 없이 통과** — syntax `--i`·`- return null;` 이 줄 중간에 있으므로 `find_diff_lines == ()` |
| T3 | 줄 가드 단독 — `render_message` 결과 어느 줄이든 `+`/`-` 로 시작하면 공백 접두 | 가드를 끄면 실패하는 입력을 하나 만든다 (그물이 항상 참이 아님을 고정) |
| T4 | syntax 안의 개행 (`"a\n+b"`) | 한 줄로 접히고, 접힌 뒤에도 줄 맨 앞이 아니므로 기호 유지 |
| T5 | term 이 비어 syntax 가 앞으로 당겨지는 경우 | term 이 비면 `· ` 머리표가 앞에 있으므로 여전히 줄 맨 앞 아님 — 확인만 |
| T6 | `_hard_wrap` 으로 syntax 가 잘려 새 줄 맨 앞에 오는 경우 | 기존 조각 가드가 공백을 붙인다 |
| T7 | 나머지 필드(term·concept·summary·질문) | 기존처럼 앞 `+`/`-` 제거 — 회귀 없음 |
| T8 | 실세션 재생 — `20260911-090702-f145/summary.json` 으로 `plan_message` | `+/*` 가 나오고 `find_diff_lines == ()` |
| 게이트 | 전체 pytest · `mypy src` · `ruff check .` | 전부 통과 |

## 6. 영향·위험

- **Discord 재전송 없음.** 이미 나간 11일 메시지는 그대로 둔다. 다음 세션부터 적용.
- 위험: 가드가 정상 줄을 바꾸는 경우 — 현재 렌더 형식에서 `+`/`-` 로 시작하는 정상 줄은 없다
  (머리표 `·`, 섹션 헤더 `[…]`, 들여쓰기 두 칸). T3 이 이를 고정한다.
- 콘솔 출력도 같은 문자열이라 같이 바뀐다. cp949 로 표현 가능한 문자만 쓰므로 인코딩 영향 없음.
